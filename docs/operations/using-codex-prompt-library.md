# Using the Codex prompt library

The controlled, versioned prompt library is under `prompts/codex/`. Directories
cover bootstrap, planning, stages, reviews, validation, maintenance, extraction,
knowledge, assessment, reporting, presentations, and templates. Templates have
`type: template` and are never active execution prompts.

Lifecycle statuses are `draft`, `active`, `deprecated`, `superseded`, and
`retired`. Stable IDs remain unchanged. Material revisions increment the
version, update the catalogue, and receive review. Obsolete prompts are not
silently repurposed.

To create a prompt, copy the applicable template, complete its YAML front
matter, keep source access and allowed paths narrow, add it to the catalogue,
and run `python scripts/validate_prompts.py`. Review scope, restrictions,
documentation impact, validation, and human-review gates before execution.

To execute interactively, from the repository root use:

    codex

then:

    Read and execute:
    prompts/codex/<path-to-prompt>.md

Codex still reads `AGENTS.md`, checks metadata and status, honors source
restrictions, works on a branch, and reports inspected files, changes,
validation, and unresolved issues. Prompts do not authorize commit or push
unless explicitly authorized.

After Stage 9.5 creates and a human approves the roadmap, use
`planning/generate-stage-prompt-from-roadmap.md` with a requested stage ID. It
reads both roadmap representations, verifies the ID, and creates only the
matching prompt; it does not execute it. Stage 10 and later prompts are not
pre-generated by this task.

Run prompt, schema, source-processing, knowledge, and test validation plus
`git diff --check`. Documentation build and link checks are not configured;
manual link review must be reported as such. `AGENTS.md` is the operating
contract, the approved roadmap governs stage scope, status files record state,
and ADRs record material architectural decisions. None replaces human review.
