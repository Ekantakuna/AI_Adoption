# Engineering platform semantic layer

This area explains reusable relationships between engineering-platform records. Canonical records remain in YAML registers.

```text
use case + capability need
  -> engineering requirement
  -> build | buy | partner | open-source | model | hosting options
  -> technical evaluation
  -> strategic choice + sourcing case + approved decision
  -> reference architecture + design patterns
  -> solution + implementation
  -> engineering and observability practices + AI UX patterns
  -> AI catalogue entry
  -> documentation + security testing + risk/control checks + compliance evidence
  -> assessment -> engineering action -> initiative
```

Provider and offering identity remains in ecosystem sourcing. Implemented status remains in current-state records. Policies, risks, controls, security acceptance and compliance conclusions remain in their owning domains.
