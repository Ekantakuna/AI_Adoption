# Knowledge risks

- **Purpose:** capture evidence-backed risk knowledge; active project risk ownership remains in project records.
- **Accepted:** Markdown risk descriptions, causes, effects, and schema-valid front matter.
- **Prohibited:** unsupported threats, active project risk status, controls presented as approved, or source excerpts.
- **Identifier prefix:** `RISK`; use `RISK-NNNNNN` and never reuse an ID.
- **Template:** `risk-template.md` (`RISK-000000` is not production).
- **Evidence requirement:** at least one valid `EVID` reference.
- **Review requirement:** AI output starts as `draft` or `needs_review`; authority requires identified human review.
- **Upstream inputs:** atomic evidence, concepts, and relevant frameworks.
- **Downstream consumers:** relationships, assessments, project risk work, outlook content, and publications.
