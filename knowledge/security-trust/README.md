# Security and trust semantic layer

This area explains reusable relationships between security-and-trust records. Canonical records remain in YAML registers.

```text
AI asset or use case
  -> trust target -> security and trust requirements
  -> threat model -> shared risk
  -> security architecture + shared control + lifecycle practice
  -> security test -> finding and remediation action
  -> assurance case -> bounded claim -> accountable human decision
  -> monitoring -> event or incident -> response and recovery
  -> assessment -> finding -> action -> initiative and metric
```

Governance owns policy, control approval, decision rights and risk acceptance. Engineering implements platform controls, data owns data-quality and metadata controls, and accountable decision authorities retain deployment and exception decisions.
