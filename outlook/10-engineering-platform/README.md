# AI engineering, platform and catalogue

This domain develops the technical environment and practices required to evaluate, design, build, integrate, operate and govern AI-powered platforms, models and applications.

- `01-engineering-strategy-and-scope/` defines technical scope, principles and domain boundaries.
- `02-requirements-and-capabilities/` defines vendor-neutral requirements and target capabilities.
- `03-build-buy-hosting-and-model-options/` compares build, commercial, open-source, cloud and on-premises alternatives.
- `04-reference-architecture/` develops logical layers, components, interfaces and deployment views.
- `05-design-pattern-library/` maintains reusable AI, prompt, context, integration, deployment and assurance patterns.
- `06-engineering-lifecycle-and-practices/` describes design, delivery, evaluation, release, reliability and retirement practices.
- `07-observability-and-operations/` defines technical, model, agent, safety, cost and outcome observability.
- `08-ai-ux-and-human-interaction/` defines transparent, controllable and accessible human-AI interaction patterns.
- `09-ai-catalogue/` defines catalogue policy inputs, discovery, inventory, documentation, assurance and lifecycle processes.
- `10-assessment-roadmap-and-reporting/` supports evidence-backed evaluation and improvement planning.

Technical evaluations inform, but do not authorize, strategic build/buy choices, provider selections, sourcing agreements, security acceptance or compliance conclusions. Canonical provider records remain in ecosystem sourcing, implemented-solution facts remain in current state, and policies, risks and controls remain in their owning domains.

No source content has been analyzed and no architecture, product, provider or model recommendation has been approved.
